# Direct3D 12.X on the host's Direct3D 12

Notes on how `d3d12_x.dll` is implemented, from getting one Unreal Engine 4
title (Xbox One, XDK era) to render. The code is in
`src/runtime/durango/d3d11x/device.cpp`, with the texture side in
`placement.cpp` and the readback probe in `layout.cpp`.

The console API looks like the desktop's, and its structures and enums are the
desktop's. What differs is everything a header can hide: the order of the
methods, a few calling conventions, and the fact that titles read and write the
objects themselves.

## Objects

`D3D12XboxCreateDevice` makes a host device at feature level 11_0. What the
title gets for each kind of object:

| Object | What the title holds | Why |
|---|---|---|
| Device | The host's device with a console vtable | Most methods are the desktop's at the same slot |
| Command queue | `QueueProxy` | Console methods past the desktop's, and DXGI needs the host's queue |
| Command list | `ListProxy`, 0x200 bytes | The title reads fields of the object (see below) |
| Descriptor heap | `HeapProxy` | Its handles are the console's, not the host's |
| Command allocator | The host's allocator with a console vtable | `SetAllocatorCallbackX` and two more console methods past `Reset` |
| Fence | The host's fence with a console vtable | `GetGpuAddressX` gives a copy of the completed value, kept current |
| Resources, pipeline states, root signatures | The host's objects | Used through desktop slots only |

A proxy is a small object with a vtable of ours that forwards to the host's
object. Whenever a proxy comes back as an argument (`ExecuteCommandLists`,
`SetDescriptorHeaps`, `ExecuteBundle`) it is replaced by the host's object.

### The device's vtable

The device keeps its identity, so everything the host hands out that leads
back to it (`GetDevice` of any child) is still the object the title knows.
Its vtable is a copy with console methods in some slots, and the host's own
vtable one slot before the first.

The host's runtime calls its device through the vtable as well, so an
overridden slot cannot simply run the console method. Each one goes through
`by_caller`, which looks at the code before the return address:

- `call [reg + slot * 8]` in the title's image: the title called this slot,
  run the console method.
- `call [reg + other * 8]` in the title's image: the title called another
  method of the host's, which jumped on to this slot. Run the host's method.
- `call rel32` to a function inside the title's image: a function of the
  title's ended in `jmp [reg + slot * 8]`. Run the console method. The
  out-of-line side of the device's inline methods is compiled this way.
- Anything else is the host calling itself.

### Method order

Device, slots 0 to 43 are the desktop's `ID3D12Device`. Console slots used so
far:

| Slot | Method | Notes |
|---|---|---|
| 0 | QueryInterface | Also answers for `IDXGIDevice1` |
| 8, 48 | CreateCommandQueue, CreateCommandQueueX | Returns a `QueueProxy` |
| 10, 11 | Create pipeline state | Console flag bits cleared |
| 13 | CheckFeatureSupport | Some console structures are larger |
| 14 | CreateDescriptorHeap | Returns a `HeapProxy` |
| 15 | GetDescriptorHandleIncrementSize | Console sizes |
| 16 | CreateRootSignature | Its tables are remembered |
| 17 to 24 | Create views, samplers, copy descriptors | Console handles translated |
| 25, 26 | GetResourceAllocationInfo, GetCustomHeapProperties | Return pointer first, object second |
| 27 | CreateCommittedResource | See resource states and flags |
| 29, 30 | CreatePlacedResource, CreateReservedResource | The same states and flags |
| 43 | GetAdapterLuid | Returned in RAX |
| 44 | CreatePlacedResourceX | A resource on memory of the title's |
| 49 to 54, 58, 69, 72, 75 | Driver hints, hang and debug callbacks, debug flags, memory priority, UnregisterPagePoolX | Accepted, no effect |
| 60 | CreateGraphicsPipelineStateX | The pipeline, without the console's extensions |
| 62 | CreateComputePipelineStateX | Two more arguments before the IID |
| 73 | CreateCommandListX | Takes a description structure |
| 74 | RegisterPagePoolX | Only hands out a handle |
| 76 | CreateCommittedResourceX | Xbox Series: the desktop's description with the console's own fields after its flags (to 0x40 bytes); the resource is the one the desktop's part describes |

Command list: slots 0 to 27 are the desktop's. The four query methods
(`BeginQuery`, `EndQuery`, `ResolveQueryData`, `SetPredication`), which the
desktop has at 52 to 55, come at 28 to 31. That pushes `SetDescriptorHeaps`
through `ClearUnorderedAccessViewFloat` four slots later, to 32 to 55. From
`SetMarker` (56) to 59 both agree again. Past that are console methods, up
to slot 103:

- 78 `DispatchX`, 83 `CopyTextureRegionX` and 84 `CopyResourceX` are the
  desktop's methods with one more argument.
- 67 `FlushPipelineX` and 68 `OMSetDepthBoundsX` are ignored, and so are
  those that only tune the console's GPU: 64 to 66, 73, 79, 82, 93, 95 to 99.
- 60 to 63 (`CopyMemoryToMemoryX`, `FillMemoryWith32BitValueX`, 64 and 128), 69, 70 and
  88 to 90 (the writes of a value or a timestamp at the top or bottom of the pipe or of a
  shader) work on memory by address, which on the console is the title's own: the CPU does
  them when the list is recorded. 71 and 72 (`Wait32BitValueX`, `Wait64BitValueX`) then
  have nothing to wait for.
- The rest report themselves the first time they are called.

Command queue: the desktop's methods up to `Wait` (15), then PIX capture
methods, `SuspendX`, `ResumeX`, `SignalX` (23), and `GetDesc` at 26.

### Calling conventions

Methods returning an 8-byte structure (`GetCPUDescriptorHandleForHeapStart`,
`GetGPUDescriptorHandleForHeapStart`, `GetAdapterLuid`) return it in RAX.
The desktop's C++ methods write it through a hidden pointer.

Methods returning a larger structure take the pointer for it first and the
object second. The desktop's take the object first.

## Fields the title reads

The console header implements part of the API inline, on fields of the
objects. A title compiled against it reads those fields from whatever object
it was given.

**Command list.** A write pointer at +0x38 and limits after it. When the
pointer is below the limit the title writes the command packet itself and no
method is called. `ListProxy` leaves all of them zero, so the comparison
fails and every command comes through the vtable.

**Device.** A flags byte (at +0x18 in the title looked at) says whether
`CreateConstantBufferView` and `CopyDescriptorsSimple` must be called out of
line. When it is zero the title does both itself:

- `CreateConstantBufferView` writes a hardware buffer descriptor at the CPU
  handle: the address plus `0x0010000000000000`, then the size divided by 16
  plus `0x0002403C00000000`. With no description it writes a null one whose
  second half is `0x0002403C00000001`.
- `CopyDescriptorsSimple`, for every heap type but samplers, copies the
  descriptors as memory, 16 bytes at a time.

The title is free to be compiled with that check removed, so the inline path
has to work whatever the byte says. Here the byte is whatever the host's
device has at that offset. It was zero on the plain device and nonzero on
the debug layer's, which made the two behave differently: see "A lesson".

## Descriptors

A console CPU handle is the address of the descriptor, below 4 GiB (titles
keep it in 32 bits). A console GPU handle is the same address.

Each heap gets shadow memory below 4 GiB, with write watch, of the console's
descriptor size per descriptor:

| Heap type | Bytes |
|---|---|
| CBV_SRV_UAV | 32 |
| Sampler | 16 |
| RTV | 112 |
| DSV | 128 |

The descriptor that counts is the host's at the same index. The shadow only
says what the host's slot holds or should hold:

- **Made through a device method.** The host's descriptor is made, and the
  shadow gets a mark followed by the host's handle of its own slot.
- **Copied by the title.** The copy carries the mark and the handle of the
  slot it came from. A marked slot that names another slot is resolved by
  copying the host's descriptor from there, after which it names itself.
- **Written by the title.** A hardware buffer descriptor. It becomes a
  constant buffer view, or a buffer SRV or UAV when the root signature says
  so, and the slot is marked.
- **Zero, or the null buffer pattern.** A null descriptor of the kind the
  table expects.

Slots are read when a table is bound (`SetGraphicsRootDescriptorTable`,
`SetComputeRootDescriptorTable`), using the ranges of the bound root
signature to know each slot's kind, and again at `ExecuteCommandLists` for
the pages the title wrote since last time. Render target and depth handles
are resolved when used (`OMSetRenderTargets` and the clears).

A copy is resolved from its source when it is first used, not when it was
made. A source slot rewritten in between would give the wrong descriptor.
Unreal copies and binds in the same breath, so this has not been seen.

## Resources

- The console's `GENERIC_READ` state is 0x8c3, without the indirect argument
  bit the desktop's 0xac3 has. Upload heaps need the desktop's value. Barrier
  states are translated the same way.
- Resource flags above 0xff are the console's and are dropped.
- A `Layout` of 0x100 or more names a tile mode. The host picks its own.
- `CreatePlacedResourceX` places a resource at an address in the title's
  memory. The host gets a committed resource instead. For textures that are
  not render targets, depth buffers or UAVs, the title's memory is tracked:
  what it writes there is read through the console's tiling with the
  package's own `xg_x.dll` and uploaded on a list of ours that runs before
  the title's, on a direct queue only.
- Buffers are remembered by GPU address, because a hardware descriptor names
  an address where a host view names a resource.

- A resource of an upload heap starts in `GENERIC_READ` and one of a readback heap in
  `COPY_DEST`, whatever the title says, and `DENY_SHADER_RESOURCE` is dropped from what is
  not a depth buffer: the host refuses anything else.
- A state with bit 0x400000 and others loses the bit. On the host it is the ray tracing
  acceleration structure, which goes with no other state.

## Rectangle lists

The console's GPU draws a rectangle from three corners: the fourth is the second plus the
third less the first, for the position and for everything interpolated. The host has no
such primitive. A pipeline of that topology type (19) gets a geometry shader of ours,
unless the title gave one: its input and output are the outputs of the pipeline's vertex
shader, read from the shader's signature, and it emits the three corners and the fourth as
a strip. Culling is turned off for it. If the host turns the pipeline down with the shader
(its compiler may pack the signature another way than the title's), the pipeline is made
without, and the triangle of the three corners is all that is drawn.

## Swap chain

The console makes its swap chain for the device. The host's Direct3D 12
wants the queue that presents, so the first direct queue the title creates is
kept for it. Typeless formats become UNORM, and `GetBuffer` passes the index
on for `ID3D12Resource`.

## Shaders

The title's DXBC has the chunks ISGN, OSGN, SHEX, RTS0 and a console one,
XHSH. The host accepts the blobs as they are.

## Diagnostics

| Variable | Effect |
|---|---|
| `XV_D3D_PROBE=<frame>` | At that frame, reads back the back buffer and the first render target of each size, logs their average colour and draw counts and writes BMPs to `%TEMP%` |
| `XV_D3D_TRACE=1` | First calls of each command list slot, handles, viewports, buffer addresses, placed resources, descriptors the title writes |
| `XV_D3D_DEBUG=1` | The host's debug layer and device removal data. 2 adds GPU-based validation, 3 is the debug layer without serialized queues |
| `XV_D3D_SLOW=<ms>` | Sleeps before every submission |
| `XV_D3D_SYNC=1` | Waits for the GPU after every submission |

## A lesson

For a long time the title rendered its title screen with the host's debug
layer on and a black frame without it, with the same draw counts. Timing was
ruled out with `XV_D3D_SLOW` and `XV_D3D_SYNC`, and queue serialization with
`XV_D3D_DEBUG=3`. The working theory became that the host's runtime tells
its objects apart by vtable, and queues and heaps were turned into proxies
for it. That changed nothing.

The cause was the device's flags byte. The debug layer's device happens to
have a nonzero byte there, so the title called `CopyDescriptorsSimple`. The
plain device has a zero, so the title copied the shadow memory itself and
the host's descriptors never followed: every texture was unbound.

When an object behaves differently depending on which host object stands
behind it, look at what the title reads from the object before suspecting
the host. The call site shows it: a `cmp byte ptr [reg + offset], 0` on the
object right before the virtual call.

## Not done

Compared slot by slot with the console header's function tables:

- Device: `CreateSamplerX` (61), the component and opaque placed resources
  (45, 77, 83, 84), the placed views (46, 47, 70, 71),
  `GetGpuHardwareConfigurationX` (68), the frame events (78 to 81), custom
  fence locations (64, 65), pipeline serialization (56, 57, 66, 67).
- Command list: `ExecuteIndirectBundleX` (74),
  `DrawIndexedX` (81), `RSSetMSAAParametersX` (80), `RSSetDepthBiasX` (94),
  predication buffers (85, 86), counters (100 to 102).
- Command queue: the page mapping methods (27 to 29), `PresentX` (30),
  `SetHDRToneMapperX` (31).
- Resources are the host's objects: the console methods past the desktop's
  (`GetPlacementDescX`) are past the end of the host's vtable.
- A fence's `GetGpuAddressX` is a CPU copy: GPU commands that take the address
  would not see it.
- Exports of `d3d12_x.dll` not there: `D3D12GetDebugInterface`,
  `D3DConfigureVirtualMemory`, `D3D10CreateBlob`.
- `OMSetDepthBoundsX` is ignored, as no host pipeline enables the test.
- Indexed quad lists are drawn as triangle lists.
- Hardware texture and sampler descriptors written by the title. Only
  buffer descriptors have been seen.
- Descriptor heaps are never forgotten once released.
- The debug layer reports resource barriers whose state before does not
  match the previous one (render target against pixel shader resource).
